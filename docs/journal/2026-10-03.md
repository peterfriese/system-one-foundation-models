## 🔨 Implementation Trajectory

### 1. Research & Analysis of Cloudflare Clef & Clef-Flash Decision Models
- **Context & Release**: Investigated Cloudflare's release of the open-weight Clef model family (`Cloudflare/clef` and `Cloudflare/clef-flash`), the first dedicated multimodal decision models in the System One ecosystem.
- **Backbone Architectures**:
  - **Clef-Flash (9B)**: Based on Qwen3.5 Multimodal Backbone, engineered for ultra-low latency edge serving (~35ms – 90ms on Workers AI edge GPUs; ~45ms – 65ms on Apple Silicon M4 Max). Ideal for real-time mobile camera framing, fast receipt triage, and interactive UI verification.
  - **Clef (27B)**: Based on Qwen3.8 Multimodal Backbone, engineered for deep multimodal reasoning (~180ms – 320ms on Workers AI edge GPUs; ~210ms – 280ms on Apple Silicon M4 Max). Designed for multi-image document inspection, KYC credential verification, and complex visual regulatory compliance.
- **Non-Autoregressive Mechanics**:
  - Unlike generative vision-language models (GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro, Llama 3.2 Vision) that decode hundreds of tokens over 1,200ms–3,500ms, Clef evaluates visual and textual state in a **single forward pass**.
  - High-resolution vision transformers process up to 4 image attachments ($\le 16\text{MP}$ each, supporting PNG, JPEG, and WebP).
  - Rank-256 Low-Rank Adaptation (LoRA) layers project joint multimodal embeddings directly into a specialized **joint schema routing head**.
  - Emits zero autoregressive output tokens (`output_tokens: 0`), computing calibrated Bayesian decision primitives directly from prefill logits.
- **Deployment Topologies**:
  - **Cloudflare Workers AI**: Edge-hosted inference via `@cf/cloudflare/clef` and `@cf/cloudflare/clef-flash`.
  - **Cloudflare AI Gateway**: Enterprise edge gateway providing response caching, rate limiting, and observability.
  - **Self-Hosted Local Inference**: Open weights runnable locally via Docker Model Runner (`docker model run hf.co/Cloudflare/clef`), vLLM, SGLang, or MLX/GGUF on Apple Silicon hardware for zero-egress offline environments.

### 2. Comparative Analysis: Clef vs. TypeSafe Jev vs. Laya
Evaluated Clef alongside existing supported backends in `SystemOneFoundationModels`:

| Capability / Attribute | TypeSafe Jev | Laya (On-Device / Serve) | Cloudflare Clef & Clef-Flash |
| :--- | :--- | :--- | :--- |
| **Model Nature** | Proprietary Cloud | Open Weights (ModernBERT / mmBERT) | Open Weights (Qwen3.8 / Qwen3.5) |
| **Parameter Size** | Cloud-scale (~70B+) | 421M (ModernBERT) / 322M (mmBERT) | 9B (Clef-Flash) / 27B (Clef) |
| **Execution Modality** | Remote REST API only | Local Apple Neural Engine Core ML or `laya-serve` | Edge Workers AI, AI Gateway, or Local Docker/vLLM/MLX |
| **Input Modality** | Text-only | Text-only | **Multimodal: Text + up to 4 Images** ($\le 16\text{MP}$) |
| **Image Types** | None | None | **PNG, JPEG, WebP** |
| **Supported Primitives** | `noul`, `choice`, `score` | `noul`, `choice`, `score` | `noul`, `choice`, `score` (Full Parity) |
| **Inference Mechanism** | Non-autoregressive forward pass | Single ANE forward pass (~12–35ms) | Single edge/GPU forward pass (~35–280ms) |
| **Autoregressive Tokens** | 0 tokens (`output_tokens: 0`) | 0 tokens (`output_tokens: 0`) | 0 tokens (`output_tokens: 0`) |
| **Confidence Routing** | Calibrated Bayesian probabilities | Calibrated softmax logits | Calibrated Bayesian probabilities |
| **Offline Execution** | Requires network & API key | 100% offline via Core ML | Offline via local Apple Silicon runner |

- **Wire Protocol Parity**: Clef maintains exact semantic parity for question primitives (`noul`, `choice`, `score`), but extends the request envelope with an optional `images` array containing base64 Data URLs (`data:image/{format};base64,...`) or structured image objects.
- **Confidence Calibration**: Clef's visual logits produce mathematically sound probability distributions, allowing seamless integration with `SystemOneCore`'s `RoutingPolicy` (`.auto`, `.confirm`, `.escalate`) for visual decision-making.

### 5. Step 1: Core Multimodal Support (`SystemOneCore`)
- **`SystemOneImage` DTO (`Sources/SystemOneCore/Models/SystemOneImage.swift`)**:
  - Supports RFC 2397 Data URLs (`data:image/{format};base64,...`) and structured base64 dictionary objects.
  - Expressive initializers accepting raw `Data`, file `URL`, MIME types (`image/png`, `image/jpeg`, `image/webp`), and Apple `UTType` (`.png`, `.jpeg`, `.webP`).
  - Flexible `Codable` implementation capable of decoding both single-string Data URLs and keyed dictionary payloads.
- **Header-Only Dimension Parsing**:
  - Implemented zero-allocation header-only dimension extraction to validate resolution limits without decompressing full bitmaps into memory:
    - **PNG**: Reads width and height directly from the 24-byte `IHDR` chunk signature.
    - **JPEG**: Scans marker segments for SOF0 (`0xFFC0`), SOF1 (`0xFFC1`), or SOF2 (`0xFFC2`) frames.
    - **WebP**: Parses RIFF header chunks for VP8 (lossy keyframe header), VP8L (lossless 14-bit width/height bitfield), and VP8X (extended 24-bit canvas dimensions).
- **Inference Guardrails**:
  - Maximum 4 images per evaluation (`Guardrails.maxImageCount = 4`).
  - Maximum 16 megapixels per image (`Guardrails.maxMegapixels = 16.0`).
  - Maximum 13 MiB total image payload size (`Guardrails.maxPayloadBytes = 13 * 1024 * 1024`).
- **`TranscriptAttachmentExtractor` (`Sources/SystemOneCore/Attachment/TranscriptAttachmentExtractor.swift`)**:
  - Extracts image data segments from Foundation Models `Transcript.Entry` attachments.
  - Matches supported `UTType` identifiers (`.png`, `.jpeg`, `.webP`) and automatically constructs `[SystemOneImage]` attachments.
- **Backward-Compatible Wire Protocol**:
  - Extended `SystemOneRequest` with an optional `public var images: [SystemOneImage]?` property.
  - Serialization excludes `images` when `nil` or empty, guaranteeing bit-for-bit wire compatibility for existing text-only backends (Jev, Laya On-Device Core ML, and `laya-serve`).
- **Consolidated `RetryPolicy`**:
  - Relocated `RetryPolicy` from `JevFoundationModels` to `SystemOneCore/Routing/RetryPolicy.swift`, standardizing RFC 9110 retry backoff across all remote backends.

### 6. Step 2: `ClefFoundationModels` Module & Swift 6.1 Package Traits
- **`ClefModel` (`Sources/ClefFoundationModels/ClefModel.swift`)**:
  - Strongly-typed enum representing Clef model variants: `.clef` (27B) and `.clefFlash` (9B).
  - Maps to official Cloudflare catalog strings (`@cf/cloudflare/clef`, `@cf/cloudflare/clef-flash`).
- **`ClefEndpoint` (`Sources/ClefFoundationModels/ClefEndpoint.swift`)**:
  - Encapsulates target infrastructure topologies into an `Equatable`, `Hashable`, `Sendable` enum:
    - `.workersAI(accountID:model:)`: Direct Cloudflare Workers AI REST API.
    - `.gateway(accountID:gatewayID:model:)`: Cloudflare AI Gateway with centralized caching, telemetry, and rate limiting.
    - `.local(port:model:)`: Zero-cloud, zero-egress local runner (`http://localhost:8000/v1/evaluate`).
    - `.custom(URL, model:)`: Arbitrary reverse proxy or dedicated endpoint.
- **`ClefHTTPBackend` (`Sources/ClefFoundationModels/ClefHTTPBackend.swift`)**:
  - Bridges `SystemOneRequest` to Clef HTTP endpoints using native `URLSession`.
  - Implements RFC 9110 retry backoff for rate limits (`429`), temporary overload (`529`), and Cloudflare-specific edge timeouts (`504`, `524`).
  - Ingests Cloudflare latency telemetry headers: parses RFC 7668 `server-timing` duration (e.g. `cfL4;dur=12, inference;dur=45`) and falls back to `x-envoy-upstream-service-time`.
  - Attaches Cloudflare AI Gateway metadata tags (`cf-aig-metadata-app`, `cf-aig-metadata-tag`) when targeting gateway endpoints.
- **`ClefLanguageModel` (`Sources/ClefFoundationModels/ClefLanguageModel.swift`)**:
  - Conforms to Apple's `LanguageModel` protocol with `ClefExecutor`.
  - Explicitly advertises both `.guidedGeneration` and `.vision` capabilities in `capabilities`, satisfying Apple's SDK gating for multimodal attachments.
  - Implements `supportsDataAttachmentType(_:)` returning `true` for PNG, JPEG, and WebP types.
- **Swift 6.1 Package Traits Integration (`Package.swift`)**:
  - Added `.trait(name: "Clef", description: "Enables Cloudflare Clef and Clef-Flash hosted and local decision models")`.
  - Included `Clef` trait in the `Remote` and `All` convenience aliases.

## 🚧 Challenges & Solutions

### 1. Foundation Models Runtime Rejection of Visual Attachments
- **Challenge**: Passing `Attachment(cgImage)` to `LanguageModelSession` initially triggered an immediate runtime trap: *"The selected model does not support image input. Consider trying again with a different model."*
- **Solution**: Investigated Apple's Foundation Models framework internals. Discovered that the SDK inspects `LanguageModel.capabilities` before dispatching to the executor. Text-only models advertise only `[.guidedGeneration]`. Updated `ClefLanguageModel` to advertise `LanguageModelCapabilities([.guidedGeneration, .vision])`, satisfying the SDK gate while retaining schema guidance. Documented in Tech Note 0013.

### 2. Dimension Parsing Without Bitmap Decompression
- **Challenge**: Validating the 16MP image resolution guardrail by instantiating `NSImage`, `UIImage`, or `CGImageSource` incurs heavy CPU and memory overhead, especially for multi-image prompts on memory-constrained mobile devices.
- **Solution**: Implemented zero-allocation header-only binary parsing in `SystemOneImage.extractDimensions(data:format:)`:
  - PNG: Read width/height from bytes 16–23 of the `IHDR` chunk.
  - JPEG: Sequentially scan marker bytes for SOF markers (`0xFFC0`–`0xFFC2`).
  - WebP: Parse RIFF/VP8 bitfields directly.

### 3. Cloudflare Telemetry Extraction
- **Challenge**: Measuring true inference latency requires distinguishing between edge model execution time and raw network transport roundtrip.
- **Solution**: Added parsing in `ClefHTTPBackend` for RFC 7668 `server-timing` headers (extracting `dur` parameters) with fallback to `x-envoy-upstream-service-time`. Ingested metrics are passed through to `Response.serverDurationMs` and `Response.transportDurationMs`.

### 4. Cloudflare Workers AI Model Schema Validation Nuance & Route Decoupling
- **Challenge**: The Cloudflare Workers AI edge route requires the full catalog name (`@cf/cloudflare/clef-flash`), but Cloudflare's input JSON schema validation restricts the `model` property to `clef` or `clef-flash` via regex `^\s*(clef|clef-flash)\s*$`. Passing `@cf/cloudflare/clef-flash` in the request body caused immediate HTTP 400 Bad Request rejections.
- **Solution**: Decoupled the URL route identifier from the request body model slug in `ClefEndpoint` and `SystemOneRequest`. The transport constructs the full catalog path for the URL while serializing the bare slug (`clef-flash`) in the JSON body. Documented in Tech Note 0014.

### 5. Cloudflare Vision Token Window Overflow (HTTP 413) & Camera Frame Optimization
- **Challenge**: Live uncompressed camera frames (~8MB) and structured image dictionary payloads triggered Cloudflare's fallback text BPE tokenizer, estimating **745,945 tokens** for a single image and rejecting the request with HTTP 413 against the 65,536 token context window.
- **Solution**: Implemented direct RFC 2397 single-string Data URL encoding (`data:image/jpeg;base64,...`) and automatic 1024px maximum-dimension downscaling with lossy JPEG (0.8 quality). This compressed camera frames from 8MB down to ~120KB, activating Workers AI's native patch tokenizer and keeping vision token usage at ~1,000 tokens well within context limits. Documented in Tech Note 0015.

### 6. Cloudflare Client API v4 Response Envelope Unwrapping
- **Challenge**: Cloudflare Workers AI API wraps execution outputs in `{ "result": { ... }, "success": true, "errors": [], "messages": [] }`. Direct `SystemOneResponse` decoding threw missing-key exceptions even on successful HTTP 200 responses.
- **Solution**: Implemented dual-decoding logic in `ClefHTTPBackend`. The decoder first inspects and unwraps the v4 `{ result: ... }` container, falling back seamlessly to direct `SystemOneResponse` decoding for local Docker or vLLM runners. Documented in Tech Note 0016.

## 📌 Key Decisions

1. **Native Apple Foundation Models Ergonomics**:
   - Visual attachments are ingested strictly through standard Apple `Attachment` and `Prompt` builder syntax. Custom session wrappers were rejected to maintain framework compliance.
2. **Explicit Advertising of `.vision` and `.guidedGeneration`**:
   - `ClefLanguageModel` advertises both capabilities, enabling multimodal prompt attachments while enforcing System One schema translation.
3. **SPM Target Isolation via `ClefFoundationModels`**:
   - Sandboxed Clef types in an isolated library target and Swift 6.1 Package Trait (`Clef`), ensuring zero overhead for consumers who only need Jev or Laya.
4. **Header-Only Lightweight Guardrail Validation**:
   - Enforce 4-image maximum, 16MP resolution limit, and 13 MiB payload constraints directly from raw byte headers prior to network transmission.
5. **Strict Real Execution Compliance (AGENTS.md Section 7)**:
   - Example apps and demonstrators never mock responses; missing credentials or local runners fail fast with formatted remediation banners and `exit(1)`.
6. **Decoupled URL Route from Body Model Slug**:
   - Distinctly separate edge route paths (`@cf/cloudflare/...`) from body model property slugs (`clef` / `clef-flash`) to satisfy Cloudflare's strict regex validation (Tech Note 0014).
7. **Single-String RFC 2397 Data URLs & Automatic Camera Downscaling**:
   - Encode visual frames as single-string Data URLs downscaled to 1024px max dimension (JPEG 0.8), shrinking payloads from 8MB to ~120KB and vision tokens to ~1,000 to prevent HTTP 413 context overflows (Tech Note 0015).
8. **Dual-Decoding Response Envelope Resilience**:
   - Gracefully unwrap Cloudflare Client API v4 `{ result: ... }` responses while maintaining backward compatibility with bare JSON payloads from local inference runners (Tech Note 0016).
