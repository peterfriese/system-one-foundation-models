## 🔨 Implementation Trajectory

### 1. Research & Analysis: OpenAI Decisions API (`gpt-6-luna`)
- **DevDay 2026 Context & Public Beta**:
  - At DevDay 2026 (September 29, 2026), OpenAI announced the Decisions API, which officially graduated to Public Beta on October 6, 2026.
  - Powered by `gpt-6-luna`—the low-latency, hyper-efficient tier of OpenAI's GPT-6 generation—the Decisions API represents OpenAI's entry into non-autoregressive, System One decision computing.
- **Dedicated Endpoint & Single Forward-Pass Architecture**:
  - Dedicated endpoint: `POST https://api.openai.com/v1/decisions`.
  - Purpose-built for discrete triage, classification, proposition validation, and score rating without conversational prose, markdown formatting, or token-by-token decoding.
  - Achieves ~150ms end-to-end round-trip latency (typically 35ms–80ms server inference)—roughly **10x faster** than autoregressive generation via the OpenAI Responses API (~1.6s).
- **Disruptive Pricing Structure**:
  - **$0.10 per 1M input tokens** and **$0.00 for output tokens** (`output_tokens: 0`). Zero output token billing eliminates financial penalties for large, multi-field schemas and complex instruction sets.
  - Zero cache-read or cache-write surcharges.
- **Multimodal Ingestion Rules**:
  - Accepts visual attachments strictly as inline Base64 Data URLs (`data:image/png;base64,...`, JPEG, WebP).
  - Explicitly rejects remote hosted URLs (`http://`, `https://`) and OpenAI `file_id` references, enforcing zero external network fetch latency on the server.

### 3. Core Implementation: `Sources/OpenAIFoundationModels/`
- **`OpenAIDecisionsEndpoint.swift`**:
  - Encapsulates target URL (`https://api.openai.com/v1/decisions`), model identifier (`gpt-6-luna`), and optional enterprise multi-tenant headers (`organization`, `project`).
  - Factory methods: `.hosted(model:organization:project:)` and `.custom(url:model:organization:project:)`.
- **`OpenAIDecisionsWireDTOs.swift`**:
  - Strongly typed, Sendable, Codable DTOs matching OpenAI's wire specification:
    - `OpenAIDecisionsRequest`: includes `model`, `input` (`.text` or `.multimodal` content blocks), `questions`, `metadata`, and optional `temperature`/`top_p`.
    - `OpenAIDecisionsQuestion`: supports question types `"predicate"`, `"choice"` (with `choices: [ChoiceItem]`), and `"score"` (with `levels: [LevelItem]`).
    - `OpenAIDecisionsResponse`: decodes `id`, `model`, `object`, `created`, `answers`, `usage`, and `error`/`refusal`.
    - `OpenAIDecisionsAnswer`: models boolean probabilities, categorical choice selections with probability arrays, ordinal score ratings, confidence values, and safety refusal blocks (`type: "refusal"`).
    - `OpenAIDecisionsUsage`: models input token consumption and enforces `outputTokens == 0`.
    - `OpenAIErrorEnvelope`: handles standard OpenAI error payloads (`code`, `message`, `type`, `param`).
- **`OpenAIDecisionsPayloadAdapter.swift`**:
  - Translates bidirectional payloads between `SystemOneRequest`/`SystemOneResponse` and OpenAI Decisions wire format:
    - Request: sorts dictionary questions deterministically by key, maps `noul` $\to$ `predicate`, `choice` $\to$ `choice` with `[ChoiceItem]`, `score` $\to$ `score` with `[LevelItem]`. Validates and converts image attachments into multimodal content blocks with RFC 2397 Data URLs.
    - Response: maps OpenAI answer arrays back into `SystemOneAnswer` instances. Handles safety refusals by throwing `OpenAIDecisionsError.refusal`.
    - Implemented defensive dictionary uniquing (`uniquingKeysWith: { current, _ in current }`) to ensure duplicate probability labels from remote endpoints do not cause runtime crashes.
- **`OpenAIDecisionsHTTPBackend.swift`**:
  - Network transport client implementing RFC 9110 retry backoff, exponential jitter, cooperative cancellation, and header injection:
    - `Authorization: Bearer <key>`
    - `Content-Type: application/json`
    - `OpenAI-Organization: <org>` (optional)
    - `OpenAI-Project: <proj>` (optional)
    - `X-Client-Request-Id: <uuid>` for idempotent tracing.
- **`OpenAIDecisionsLanguageModel.swift` & `OpenAIDecisionsExecutor.swift`**:
  - Conforms to Apple's `FoundationModels.LanguageModel` protocol.
  - Advertises `.guidedGeneration` and `.vision` capabilities.
  - Supports data attachment types `.png`, `.jpeg`, and `.webP` (rejecting non-image types such as PDF and plain text).
  - Bridges Foundation Models generation schema into System One request schema, executing via `OpenAIDecisionsExecutor` and streaming single-frame JSON delivery via `LanguageModelExecutorGenerationChannel`.
- **`MockOpenAIDecisionsBackend.swift`**:
  - Deterministic offline mock implementation supporting custom request interceptors, synthetic answers, and latency simulation without live network calls.

## 🚧 Challenges & Solutions

### 1. Wire Schema Impedance Mismatch (Dictionary vs. Ordered Array)
- **Challenge**: Existing System One backends (TypeSafe Jev, Cloudflare Clef) structure questions and answers as key-value dictionaries (`questions: [String: Question]`, `answers: [String: Answer]`). OpenAI Decisions mandates ordered arrays (`questions: [OpenAIDecisionsQuestion]`, `answers: [OpenAIDecisionsAnswer]`), renames boolean types from `noul` to `predicate`, structures choices into `[{value, description}]`, and structures rubric scores into `levels: [{label, description}]`.
- **Solution**: Developed `OpenAIDecisionsPayloadAdapter` as a dedicated bidirectional translation layer. The adapter deterministically sorts incoming question keys alphabetically to ensure consistent payload generation, maps primitives to OpenAI's schema conventions, and unpacks answer arrays back into dictionary structures expected by `SystemOneResponse`.

### 2. Strict Multimodal Ingestion Constraints & RFC 2397 Data URLs
- **Challenge**: OpenAI Decisions API strictly rejects remote HTTP/HTTPS image URLs and OpenAI `file_id` references, accepting images only as RFC 2397 inline Base64 Data URLs (`data:image/png;base64,...`, JPEG, WebP). Passing an unsupported MIME type or an invalid format causes immediate HTTP 400 rejection.
- **Solution**: Implemented `OpenAIDecisionsAttachmentValidator` and `EmailAttachment.utType` mapping. Attachments are inspected for valid MIME types and file extensions, validated for non-empty byte buffers, and encoded directly into Base64 Data URLs. Non-image types (such as PDF or plain text) are rejected early with informative typed errors.

### 3. Defensive Probability Key Uniquing
- **Challenge**: During code review, it was noted that remote API responses containing duplicate labels or values in choice/score probability arrays would cause Swift's `Dictionary(uniqueKeysWithValues:)` initializer to trap with a runtime precondition failure.
- **Solution**: Replaced `Dictionary(uniqueKeysWithValues:)` across all probability and legend mapping blocks in `OpenAIDecisionsPayloadAdapter.swift` with `Dictionary(..., uniquingKeysWith: { current, _ in current })`, ensuring defensive handling that preserves existing values without crashing.

### 4. Multi-Tenant Enterprise Header Propagation
- **Challenge**: Enterprise OpenAI accounts frequently require routing API calls through specific organization and project boundaries (`OpenAI-Organization` and `OpenAI-Project` headers) for access control and cost attribution.
- **Solution**: Added optional `organization` and `project` parameters to `OpenAIDecisionsEndpoint`, stored them in `BackendConfigurationStore`, and injected them into all outbound HTTP requests in `OpenAIDecisionsHTTPBackend` and `BackendHealthProbeService`.

## 📌 Key Decisions
1. **Dedicated `OpenAIFoundationModels` Target & Swift 6.1 Trait**: Isolated OpenAI client logic into a separate SPM target gated behind `.trait(name: "OpenAI")`, preventing unnecessary dependency bloat for on-device or Clef-only deployments while maintaining clean package architecture.
2. **Strict Real-Execution Fail-Fast Mandate**: In full compliance with `AGENTS.md` Directive 7, `Examples/OpenAIDemo/` contains zero synthetic mocks or offline bypasses. Missing API keys trigger a clear remediation banner and terminate with `exit(1)`.
3. **OpenAI Decisions as 7th MailTriageApp Backend**: Positioned `MailTriageApp` as a universal testbed and showcase supporting seven distinct execution topologies: On-Device Core ML, Local Serve, Hosted VPC, Cloud API (Jev), Cloudflare Clef, OpenAI Decisions, and Apple Intelligence Baseline.
4. **Defensive Probability Key Uniquing**: Adopted non-crashing dictionary construction with conflict resolvers across all response adaptation logic to protect against malformed or duplicate upstream payloads.
5. **Adaptive Parallelism**: Constrained batch triage parallelism to 4 for remote cloud backends (`.cloudflareClef`, `.cloudAPI`, `.openaiDecisions`) to prevent rate-limit saturation while retaining higher parallelism (8) for local backends.
