## 🔨 Implementation Trajectory

### 1. Research & Analysis: Google Gemini Decisions API (`gemini-decision-1`)
- **Dedicated Non-Autoregressive Endpoint**:
  - Reviewed the Google AI Studio Decisions API specification (`https://aistudio.google.com/docs/decisions-api`), hosted at `POST https://generativelanguage.googleapis.com/v1beta/decisions` and powered by `gemini-decision-1`.
  - Designed for high-density classification, boolean policy verification, categorical routing, and ordinal rubric scoring in a single non-autoregressive forward pass (~150ms–250ms median latency).
- **Scale & Unit Economics**:
  - Supports up to **1,000 independent questions** evaluated simultaneously against a shared **256K (262,144) token** multimodal context window.
  - Priced at **$0.10 per 1M input tokens** and **$0.00 per 1M output tokens** (`output_tokens: 0` / `candidatesTokenCount: 0`), eliminating output token cost scaling across large `@Generable` schemas.
- **Native System One Dictionary Schema**:
  - Unlike OpenAI's Decisions API (which wraps questions/answers in ordered arrays and renames `noul` to `predicate`), Google Gemini Decisions natively uses dictionary-keyed `questions: [String: Question]` and `answers: [String: Answer]` with `noul`, `choice`, and `score` primitives.
- **Multimodal `parts` & Raw Base64 `inline_data`**:
  - Accepts plain string `"input"` for text-only state, or Gemini `ContentItem` blocks (`[{"role": "user", "parts": [{"text": "..."}, {"inline_data": {"mime_type": "image/png", "data": "<raw_base64>"}}]}]`) when visual attachments (`PNG`, `JPEG`, `WebP`) are present.

## 🚧 Challenges & Solutions

### 1. Raw Base64 `inline_data` vs. RFC 2397 Data URLs
- **Challenge**: `SystemOneImage` stores visual payloads internally as RFC 2397 Data URLs (`data:image/png;base64,iVBORw0KGgo...`) for compatibility with OpenAI and Cloudflare endpoints. However, Google's Generative Language API (`generativelanguage.googleapis.com`) rejects `data:` URI prefixes inside `inline_data.data` with HTTP 400 `INVALID_ARGUMENT`.
- **Solution**: Validated image attachments via `GeminiDecisionsAttachmentValidator` and extracted `image.format.rawValue` (`mime_type`) alongside `image.base64DataString` (which strips the `data:<mime>;base64,` prefix) when constructing `GeminiDecisionsRequest.InputPayload.Part.inlineData`.

### 2. Wire Variations Across Direct Edge and Cloud Gateways (`usage` vs. `usageMetadata` & Field Aliases)
- **Challenge**: Responses from `/v1beta/decisions` and Google Cloud / Vertex AI gateways can report token counts under either snake_case `"usage"` (`input_tokens`, `output_tokens`) or camelCase `"usageMetadata"` (`promptTokenCount`, `candidatesTokenCount`), and may emit boolean scores under `"noul"` or `"probability"` and categorical winners under `"choice"` or `"selected"`.
- **Solution**: Implemented custom `init(from: Decoder)` logic in `GeminiDecisionsResponse` and `GeminiDecisionsAnswer` that normalizes all field aliases and exposes a unified `resolvedUsage` property.

### 3. Distinguishing Transient Rate Limits from Hard Quota Exhaustion on HTTP 429
- **Challenge**: Google's RPC error envelope returns HTTP 429 (`RESOURCE_EXHAUSTED`) for both momentary per-minute rate limits and hard billing/quota exhaustion. Retrying a hard quota exhaustion wastes time and masks the root cause.
- **Solution**: Implemented `isQuotaExhaustion(detail:rawMessage:)` in `GeminiDecisionsHTTPBackend` to inspect the Google RPC error message for quota/billing exhaustion indicators and fail fast with `SystemOneError.quotaExceeded`, while retrying transient 429 responses using RFC 9110 `Retry-After` headers.

## 📌 Key Decisions
1. **Dedicated `GeminiFoundationModels` Target & `Gemini` SPM Trait**: Isolated Google Gemini Decisions support in `Sources/GeminiFoundationModels/` gated by `.trait(name: "Gemini")` and included in `Remote` and `All` trait bundles.
2. **Ergonomic `GeminiLanguageModel` Typealias**: Provided `public typealias GeminiLanguageModel = GeminiDecisionsLanguageModel` so call sites can use either concise `GeminiLanguageModel()` or explicit `GeminiDecisionsLanguageModel()`.
3. **Dual Environment Variable Resolution (`GEMINI_API_KEY` $\to$ `GOOGLE_API_KEY`)**: Supported both standard environment variables used across Google AI Studio and Google Cloud SDKs, transmitted exclusively via the `x-goog-api-key` header.
4. **Principle 7 Fail-Fast CLI Demo**: `gemini-demo` strictly requires a real API key and exits with code `1` and a remediation banner when unconfigured.
